PARTE 2 — ASPECTOS DE PROGRAMAÇÃO EM JAVASCRIPT
Projeto: SquadHub

1. Operadores relacionais e lógicos

Critério da atividade: Relacionar os operadores relacionais e lógicos estudados com o JavaScript usado no projeto e explicar o raciocínio.

Resposta: No cadastro, o JavaScript usa comparações para validar os campos. Em cadastro.js, a senha é verificada pelo tamanho mínimo (valor.length >= requisito.minimo), por padrões de caracteres e pela comparação entre senha e confirmação (valorSenha !== valorConfirmacao). Há também verificações de vazio (valorConfirmacao === "" e valorSenha === ""). Essas expressões resultam em verdadeiro ou falso e orientam a próxima ação do programa. No login (login.js), email === emailCorreto e senha === senhaCorreta são combinados com o operador lógico &&: o acesso só ocorre quando as duas comparações são verdadeiras.

2. Estruturas condicionais IF/ELSE

Critério da atividade: Destacar o uso de IF/ELSE e relacioná-lo à lógica estudada.

Resposta: O cadastro usa if/else para verificar requisitos da senha e tratar situações da confirmação: campo vazio, senha original ausente, senhas diferentes ou correspondentes. Cada condição conduz a uma resposta apropriada, como exibir uma mensagem, aplicar feedback visual ou marcar o campo como inválido. A lógica é sequencial: primeiro são tratados os casos que impedem a validação; se nenhum deles ocorrer, as senhas são consideradas iguais. O login também usa uma condição para decidir entre redirecionar para a página inicial e informar que as credenciais estão incorretas.

3. Estrutura SWITCH CASE

Critério da atividade: Relacionar o uso de SWITCH CASE ou justificar sua ausência.

Resposta: Não foi identificado uso de switch/case no JavaScript atual. As decisões do projeto são verificações booleanas simples (por exemplo, senha válida ou inválida), que são atendidas diretamente por if/else. Um switch seria adequado se houvesse seleção entre vários casos fixos, como categorias ou opções de navegação; essa necessidade não aparece nas funcionalidades implementadas atualmente. Portanto, não foi incluído apenas para cumprir uma estrutura sem necessidade funcional.

4. Estruturas de repetição FOR, WHILE e DO-WHILE

Critério da atividade: Destacar e explicar as estruturas de repetição usadas, considerando a lógica estudada.

Resposta: Em cadastro.js existe um laço for que percorre o array listaRequisitos, do índice 0 até o último item. Para cada requisito, o programa obtém o elemento correspondente, verifica se a senha o satisfaz e atualiza a interface. A quantidade de verificações é conhecida pelo tamanho do array, por isso o for é adequado. O código atual não utiliza while nem do-while. Não há processamento que dependa de repetir uma ação até uma condição futura ou que precise executar ao menos uma vez; os eventos de digitação chamam as funções quando necessário. Esses laços poderão ser considerados se surgirem fluxos que realmente exijam repetição condicional.

5. Arrays, vetores ou matrizes

Critério da atividade: Criar ou revisar funcionalidades com arrays, vetores ou matrizes; caso não sejam usados, justificar.

Resposta: O projeto já utiliza um array de objetos chamado listaRequisitos, em cadastro.js. Cada posição representa um requisito da senha e contém seu identificador e a regra de validação (tamanho mínimo ou expressão regular). O laço for percorre esse vetor para verificar todos os critérios e atualizar sua indicação visual. Essa organização evita repetir manualmente a mesma lógica para cada requisito e facilita adicionar, remover ou alterar regras. Não foi identificada necessidade atual de matriz (array bidimensional): as informações verificadas são uma lista simples de requisitos, sem relação de linhas e colunas.

6. Relação com a lógica de programação e Java na Fase 3

Critério da atividade: Explicar a linha de raciocínio dos conteúdos sob a perspectiva de lógica e dos assuntos estudados sobre Java.

Resposta: O raciocínio aplicado é independente da linguagem: obter dados, avaliar condições booleanas, escolher um caminho e apresentar o resultado. O array guarda um conjunto de regras; o for percorre esse conjunto; as condições if/else determinam o tratamento de cada situação. Esses conceitos também aparecem em Java, embora a sintaxe e as APIs sejam diferentes. Assim, a implementação em JavaScript ajuda a praticar conceitos fundamentais de lógica que podem ser reconhecidos e reaplicados em Java.

7. Limites atuais da implementação

O JavaScript do cadastro oferece validação visual e validação de formulário no navegador. O login compara os dados com valores fixos definidos no próprio arquivo login.js. O projeto, no estado atual, não demonstra autenticação conectada a servidor, armazenamento de contas ou banco de dados. Portanto, o comportamento deve ser entendido como protótipo acadêmico, e não como autenticação pronta para uso real.
